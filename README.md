## 決めごと

- cpsbvbng26-dotcom の決めごと 15 により、独学の成果は学部一年次までのものです。
- 独学の系列に、新しい主題を足しません。
- 実験は、決めごと 15 が挙げる経路のどれかで進めるときだけ置きます。
- 経路は、共同研究・JOSS・学会発表・ダイヤモンド・オープンアクセスの場です。
- 経路が決まっていない実験は、置きません。
- 掲載料や投稿料を取る場には出しません。cpsbvbng26-dotcom の決めごと 14 によります。
- 事前の計画は、データを見る前に固め、その日を書きます。
- 計画を変えたら、変えた日と理由を足します。前の計画は消しません。
- 結果は、問いに答えられなかったときも書きます。
- 社会の制度や教育の政策を主題にするときは、cpsbvbng26-dotcom の[利益相反の記録](https://github.com/cpsbvbng26-dotcom/cpsbvbng26-dotcom/blob/main/docs/conflicts-of-interest.md)の「眠っている利益相反」の条件に従い、開示を冒頭に置きます。

## 実験の雛形

実験は、`experiments/` に、実験ごとにディレクトリを作って置きます。
各ディレクトリは、`template/` の雛形を写した文書と欄を持ちます。

| ファイル | 中身 |
| --- | --- |
| [`template/experiment.md`](./template/experiment.md) | 実験の文書。日本語 |
| [`template/experiment.en.md`](./template/experiment.en.md) | 実験の文書。英語 |
| [`template/experiment.json`](./template/experiment.json) | 実験の欄 |

文書の見出しは、次の順に並びます。

| 見出し | 書くこと |
| --- | --- |
| 問い | 確かめられる形の問い |
| 経路 | 決めごと 15 が挙げる経路のどれか |
| データの出所とライセンス | データの所在、ライセンス、確かめた日と所、個人のデータを含まないこと |
| 方法 | 何を数え、どう比べるか。道具とその版 |
| 事前の計画 | データを見る前に固めた問い・仮説・分析・止める条件と、その日 |
| コード | コードの所在と、結果を作り直す手順。乱数の種 |
| 結果 | 計画した分析の結果を先に。計画に無かった分析は分けて |
| 限界 | 言えないこと |
| 開示 | 利益相反と、言語モデルの使い方 |

| 欄 | 中身 |
| --- | --- |
| `name` | 実験の名。ディレクトリの名と同じ |
| `status` | `planned`・`running`・`done`・`withdrawn` のどれか |
| `route` | `collaboration`・`joss`・`conference`・`diamond-oa` のどれか |
| `question` | 問い |
| `data_source` | データの所在 |
| `data_licence` | データのライセンス |
| `licence_checked` | ライセンスを確かめた日 |
| `personal_data` | `none` だけ |
| `plan_fixed` | 事前の計画を固めた日 |
| `results_written` | 結果を書いた日。計画を固めた日より後 |
| `code` | コードの所在 |

## データの倫理

- 個人のデータを使いません。
- 個人を特定できるデータと、特定できる形に戻せるデータも使いません。
- 公開されたデータだけを使います。
- 人を対象にした調査や収集を、新しくすることはしません。
- データのライセンスを確かめてから使います。確かめたライセンスと、確かめた日と所を記録に書きます。
- 再配布を許さないデータは、ここに置きません。所在と取り寄せ方だけを書きます。
- 機械での取得を規約が禁じる場からは、データを取りません。
- 複数のデータを組み合わせて、人を特定できるようにすることはしません。

## 検査

```
python3 verification/check.py            # 雛形の見出しと欄・実験の欄と経路と日付・データの倫理・決めごと・写し・書き方・数
python3 verification/check.py --break    # 検査を一つずつ壊し、落ちることを確かめる
```

実験が無いうちは、実験の欄の検査は、検査の中で作った見本の実験に当てて、通ることと落ちることを確かめます。
CI は、この検査を push と PR のたびに回します。
